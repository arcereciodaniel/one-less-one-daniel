# V15.6c — explicit period identity and restore rehearsal

Explicit flexible rows have stable date-range keys, independent start/end, frequency, start-month label and fortnight=0 sentinel. Migration uses the explicit key instead of merging same-month rows. Restore rejects duplicate explicit identities and overlapping dates. Date lookup stops beyond the explicit end; canonical legacy dates are retained. New income occurrences prefer the explicit period covering the actual date. Pure query core supports exact period and calendar intervals; financial month/quarter grouping for mixed calendars is explicitly blocked until its semantics are implemented. The existing settings transition runs a real restore/migration rehearsal on a clone and reports the number of preserved rows; no activation, no live materialization, no write of new periods. Legacy filter, editing, quarter creation, mobile and reporting adapters still require work before activation. No CSS or deployment changes. Existing V14 adjustments and actual ledger remain unverified.
