# V16.2 · Motor temporal de asignaciones

Cada asignación nueva contiene ID, categoría, fecha exacta, importe y moneda. No hay frecuencia en la categoría. La misma categoría aparece una o varias veces según sus asignaciones; semana, quincena, mes, trimestre, semestre y año agrupan por fechas. Si una semana cruza una quincena, la fecha concreta decide dónde pertenece el dinero. No se presume fecha de pago a partir de un gasto real. Una futura recurrencia será un generador opcional de asignaciones fechadas, no otro presupuesto ni una configuración de la categoría.

## Compatibilidad histórica
Adaptador puro de solo lectura, sin migración ni escrituras. Preserva períodos financieros originales y sus meses de referencia; la consulta financiera histórica usa claves de período, y la consulta calendario usa fechas. Los montos originales sin fecha se mantienen como intervalos completos; una consulta parcial informa pendiente, no cero disponible ni reparto inventado. Distribuciones semanales válidas de V15 sustituyen la representación del monto padre, nunca se añaden encima. Si cambian o están incompletas, vuelve el intervalo original y se informa revisión. Única fecha válida de ingreso automático dentro del período permite asignar el monto original; varias fechas no se separan sin conocer el importe individual. Ajustes V13/V14 se marcan pendientes, no se ignoran como si estuvieran reconciliados.

Movimientos por fecha real, con posibilidad de consultar asignación financiera histórica; splits conservan los importes originales y deben cuadrar, aportes a meta se incluyen una sola vez como ahorro; los gastos financiados se conservan como gasto presupuestario, no se pretende calcular saldo operativo. CRC y USD se mantienen separados con unidades menores enteras. Conversión explícita de plan usando tasa de compra/venta actual; histórico con la tasa guardada, ausencia señalada sin conversión implícita. No se migran datos reales, no se modifica el motor de producción, no se persisten asignaciones nuevas ni se conectan todavía a saldos/Futuro. El prototipo V16.1 de navegación sigue usando su fixture propio; el motor V16.2 tiene pruebas específicas con datos de formato V16.0.
