# V16.3 — Editor universal de asignaciones

Rama aislada sobre V16.2. El editor usa el motor normalizado real V16.2 para consultas; no escribe en la aplicación publicada. Datos ficticios, memoria volátil, CRC/USD separados. Cada operación se prepara y confirma explícitamente: alta por fecha, edición de fecha/monto de una asignación nueva, eliminación explícita, repetición con cantidad finita y distribución de un intervalo histórico. Recurrencia mensual conserva día original cuando existe y ajusta al último día de meses cortos. Una repetición con conflicto de categoría/fecha/moneda se rechaza completa, no agrega parcialmente. No hay frecuencia obligatoria de categoría.

Distribuir conserva exactamente los importes de origen y su moneda, reemplaza el intervalo por asignaciones fechadas, dentro del intervalo, mantiene parentKey y financialMonth cuando existen. No convierte automáticamente gastos reales en presupuesto; el importe sugerido de un gasto sin presupuesto requiere confirmar. Una asignación nueva que pisa un intervalo pendiente exige distribuir primero. No se altera el historial de movimientos, metas ni saldo. No se cambia moneda de una asignación existente sin operación explícita; presupuestos de origen histórico no se eliminan ni cambian de monto, ingreso automático queda bloqueado. Vistas previas inválidas o desactualizadas no se aplican.

## UI
Una tarjeta por intervalo, botón Asignar, desplegable Asignaciones para editar por fecha, botón Distribuir en montos pendientes, formulario breve con repetición opcional. Revisión muestra fechas y variación por moneda. Presupuesto e Inicio consultan el mismo modelo en memoria; Movimientos usa sus hechos originales. Futuro y Proyectos conservan navegación demostrativa. Demo no admite respaldo real, conexión móvil, almacenamiento ni restauración. No se modifica CSS de producción ni main. Pendientes: persistencia transaccional real y migración/reconciliación de históricos, conexión a los demás módulos, inteligencia y validación visual. Las decisiones de recurrencia, conflictos y límites calendario son explícitas y deben revisarse antes de lanzar.
